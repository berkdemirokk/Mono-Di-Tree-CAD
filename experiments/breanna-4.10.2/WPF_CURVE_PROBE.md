# Isolated C# curve and glyph vertical slice

This experiment is a separate `net10.0-windows` console probe under this directory. It does **not** modify `PatternPiece`, `ProjectDocument`, the production project codec, desktop editor, DXF, nesting, machine gateway or plotter. The production model is still a point list with notches tied to vertex indices, so silently adding cubic or independent glyph fields to it would cause data loss or unsafe downstream behavior. A production implementation still needs a versioned document/model change, complete downstream rejection or support, editor/undo semantics, rendering, migration, provenance and validated geometry and licensing.

The probe consumes only the generated fixed synthetic fixture from `wpf-curves-fixture.mjs`, derived from the isolated `synthetic-curves.v2` example. Its own distinct envelope `tekstilcad.synthetic.wpf-curves`, version 1, stores named pieces, ordered move/line/cubic/close operations and named `notch`/`bnotch` glyphs with six-element affine matrices in mm. It explicitly records omitted allowance, grainline, cutlist, source SVG styling and unverified production boundary. Only the two observed notch shapes are rendered; their diagnostic colors and stroke styling are not the original SVG styling. Topology, fit, licensing and production approval remain false. This is not a complete FreeSewing representation or a stable production project format.

The C# codec rejects unknown/missing/duplicate fields, unsupported version or operation, malformed cubic controls, missing or unknown marks, nonfinite/out-of-range coordinates, singular matrices, changed omission flags, extra contours and unclosed seam commands. It has input size and no-EOF time limits. It writes a unique synthetic experimental file, reopens it and compares the reserialized bytes. Separately it writes synthetic legacy data using the actual `ProjectStorage`, reopens both its unversioned form and a version-1 wrapper with that existing reader, and confirms that the production reader rejects the experimental envelope. This demonstrates these two legacy cases, not every historical project variant; no automatic upgrade or full product-level save/open integration is implemented.

The preview uses WPF `PathGeometry` and `BezierSegment` without flattening and draws the notch and bnotch glyph geometry under their matrices. It renders offscreen to a PNG inside the ignored `wpf-curves-probe/runtime` directory; no window is created. The conservative viewport includes the cubic control hull and transformed glyph bounds. Source coordinates are millimetres, but the bitmap is fitted to the window and is not physically calibrated. The image is explicitly labelled synthetic and not for production. No proof of simple topology, glyph-edge attachment, seam allowance, fit, manufacturing suitability or legal clearance follows from drawing it.

Tests use the checksum-verified isolated Node and local .NET runtime. They cover the C# disk roundtrip, two old-format reads, rejection by the production reader, WPF Bezier control preservation, 2x scale/translation, glyph count, malformed/unknown/duplicate inputs, unsupported versions, disallowed production flags and input timeout. The source glyph definitions and FreeSewing/hooks licensing remain unresolved; the experiment must not be redistributed as a cleared production product. No user measurements, WearCAD files or machine are touched.

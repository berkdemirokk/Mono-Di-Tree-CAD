# Synthetic curve-document experiment

`PatternPiece` in the existing core stores a list of points, a closed flag, and visual notches attached to existing vertex indexes. It cannot represent cubic control points, an independent open allowance path, or a source notch glyph and its affine basis without loss. Persistence, rendering, grading, nesting and other code use this point model. This experiment therefore does not convert to `PatternPiece`, change the application file model, or expose an import/export/production interface.

The isolated `synthetic-curves.v1` JSON contract holds three fixed piece roles, millimetre units, cubic move/line/curve/close operations, distinct seam and optional allowance paths, explicit allowance closure, source annotation path, named notch definitions, source precision anchor and SVG-rounded anchor, and a separate source-to-current affine matrix per piece. A notch's glyph transform includes the full affine linear basis and the transformed SVG anchor. Source glyph definitions themselves are not embedded. Cutlist, validated edge correspondence, sewing fit and a verified cut boundary are not included. An explicit loss list and `transferable`, `productionApproved`, `topologyVerified`, and `licenseVerified` flags remain false; the production conversion gate always rejects. Validation does not establish authenticity of a document or its claimed source.


## Explicit source omissions

This is **not a lossless representation of the complete FreeSewing source or SVG**. The required `losses` array lists, by name or category: the source parts `breanna.base`, `breanna.frontBase` and `breanna.sleevecap`; hidden `saBase` and `sleevecap` paths; `secondaryBustDartHint`, `primaryBustDartHint` and `waistDartHint`; the imperial and metric scalebox paths; and the `logo` snippet. It also records that source object attributes, named points and `noop` operations, the cutlist and other metadata are omitted. Some of these items occur only on particular pieces or option combinations; listing them is conservative and does not assert that every item occurs in every draft.

The annotation retained here is the unrounded intermediate path and its semantic name. The separate SVG-rounded annotation `d`, rendered text, marker IDs and marker definition contents are not embedded. Notch definition names, anchors and glyph transforms survive, but the actual SVG notch definitions and source styling do not. Therefore reproducing the complete source SVG or every source mark from this JSON alone is not possible. A separate visual preview may use the upstream definitions; it is not part of this document.

The exact mandatory loss list is validated on creation, transformation and parsing. Removing or changing an entry fails closed. Since this is a private experiment with no compatibility guarantee, previous `synthetic-curves.v1` examples with the shorter list are rejected and must be regenerated; this does not migrate production data.
The example generator accepts no external input. It uses the fixed synthetic Breanna draft with 10 mm allowance, validates the source marker evidence and uses the source group translations. `synthetic-curve-example.json` is diagnostic test data only; it is not a TekstilCAD project, a production file, a plotting file or a format stability promise. In this sample the seam has an explicit closing command, the front allowance is open, and a source front line has zero length. Explicit closure does not prove a simple contour, and an allowance is not automatically a cutting boundary.

For the selected seam, allowance and annotation paths only, the document retains their supplied binary64 coordinates and cubic controls on JSON serialization/reparse without polyline flattening, subject to JSON's normalization of negative zero. Applying an affine transform uses ordinary binary64 arithmetic and is not mathematically exact or a certified geometric/topological error bound. SVG-rendered notch anchors were independently rounded to 0.01 mm and matched to the intermediate anchor within 0.0051 mm on each axis. After affine linear part `[a c; b d]`, a conservative real-arithmetic bound on this input discrepancy is `sqrt(2)*0.0051*sqrt(a²+b²+c²+d²)` mm; floating-point rounding is additional and not formally bounded here. Never treat this as proof of notch attachment or cutting validity.

Tests exercise JSON roundtrips, rotations, anisotropic scaling, per-piece placement, composed transforms, glyph basis, missing allowances, unknown commands, forged flags, singular/nonfinite/oversized transforms, extra fields and duplicate-key JSON. No user measurements, production CAD document, machine or plotter is touched. FreeSewing and hooks attribution remains unresolved in `PUBLIC_LICENSE_RESEARCH.md`.

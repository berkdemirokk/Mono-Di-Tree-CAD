# Isolated official Node validation — 2026-11-02

The official Windows x64 Node.js v24.22.1 executable was downloaded only into this experiment's ignored `runtime-official` directory from [nodejs.org](https://nodejs.org/dist/v24.22.1/win-x64/node.exe). The [official SHA-256 list](https://nodejs.org/dist/v24.22.1/SHASUMS256.txt) was downloaded alongside it. The list's `win-x64/node.exe` entry and the downloaded executable both hash to `d702daa815eabbff763c7d3808e235cf031cf2ca70211b56847bc72f51e240e5`. The downloaded checksum file hashes to `fdfbffc969c0f604beff0124d409b33a43b53f5c681d6220f80023e0d6df9dc4`. The checksum was compared before executing the binary; the SHA-256 list's signature was not verified. HTTPS retrieval and matching a checksum alone are not signature verification.

The copy of the [official version-tag Node LICENSE](https://github.com/nodejs/node/blob/v24.22.1/LICENSE) was placed beside the executable from the previously downloaded research copy. Its SHA-256 is `5888dbb9a1d2b18f2c3e6c5f6af1b39de658372b402a0577b002777f14c62ace`. The official executable reports `v24.22.1`. It was invoked explicitly without modifying PATH, system Node, application configuration or production files. Using this executable, all 93 synthetic Node tests passed, including the local read-only garment preview, isolated Windows worker and the checksum/notice artifact test. The existing .NET probes were reused; no production data or hardware was used. The binary and downloaded runtime artifacts are ignored by Git and are not a distribution package.

`verify-official-node.ps1` reproduces the HTTPS download, checks the published hash against the fixed observed hash and the executable, verifies the saved license copy, and then runs the synthetic suite using the isolated executable. It does not verify upstream signatures. The artifact test checks present local bytes and skips if the ignored binary is absent; it does not download anything.

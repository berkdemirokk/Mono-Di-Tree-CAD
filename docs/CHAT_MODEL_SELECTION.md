# Model selection from Turkish chat

The request composer recognizes explicit model-choice messages using a deterministic local grammar. Supported model IDs are the existing `wrap`, `aline`, `corset`, `sheath`, `straight`, `shirt` IDs. Turkish dotted/dotless I and uppercase ASCII spelling are handled only in a temporary comparison copy. Supported alternatives include `a-kesim`, `balenli korsaj`, `kılıf elbise`, `düz kesim elbise`, and `gömlek tipi elbise`. This is not AI inference and has no network or paid-service dependency.

An exact model name can be prefixed by `lütfen`, `modelim`, `model olarak`, or `model seçimi`, and followed by `istiyorum`, `seç`, `seçelim`, or `olsun`. One such clause can appear alongside comma/semicolon/newline-separated affirmative detail clauses and explicit measurements, e.g. `A kesim elbise istiyorum, uzun kollu; bel çevresi 72 cm`. Supported detail vocabulary covers sleeve, neckline, length, color and fabric values listed in `ChatModelChoice`; arbitrary prose is not assumed affirmative. Conflicting values in one attribute category or contradictory measurements veto the suggestion. Decimal commas in measurements remain intact. Unknown clauses, multiple/repeated model clauses, negation, conditions, uncertainty, questions and quotation marks prevent suggestions. Exact model names alone remain explicit selection requests. General adjectives alone never identify a model. All original text is retained; this is not general Turkish understanding.

The normal Send handler retains the message before asking for confirmation. Declining retains the message and existing selection. Accepting selects the existing card and portable ID; request changes during the confirmation invalidate the action. Previous conflicting prose is retained and the confirmation explicitly calls attention to it. V1 approval explicitly includes conversion to V2 so model identity can be stored without replacing the user's text; V1 export loses model identity, as disclosed. Existing manual-card V1 behavior is unchanged. Request storage validation, reference decoding, and pattern geometry are unchanged. There is no automatic pattern creation.

Unit tests exercise all six identities, Turkish/ASCII casing, aliases and negative/multiple/quoted/mixed cases. `TekstilCAD.Studio.exe --verify-chat-model <new-report.json>` constructs an unshown owner HWND and exercises real Send logic, injected yes/no confirmations, model-card highlighting, V1/V2 behavior, exact text preservation, serialization, ambiguous refusal and stale approval. The report never overwrites another report. Tests/build were not run by this agent; the coordinator owns execution. This is not interactive device verification.

A V1 request containing a reference image now passes the existing V2 serialization/decoder validation and explicit conversion confirmation inside the chat flow. After successful unchanged conversion, the same original message is analyzed again without appending it; model selection still needs a separate confirmation. Failed image validation, cancelled conversion or changed draft/message stops selection and retains original bytes. An in-progress image operation also blocks selection. This is a synchronous flow, not a persisted pending-message queue; cancellation does not schedule a later automatic selection.

The confirmation snapshot includes V1 model tracking fields, dirty state and reference revision in addition to serialized request values. Any change cancels the pending selection. Regression coverage includes a tracking-only mutation and long descriptions with conjugated negation such as `tercih etmiyorum`, `düşünmüyorum`, and `olmayacak`; all fail closed rather than relying on a small negation blacklist.

Only the analysis copy is normalized to Unicode Form C before case folding. Decomposed Turkish letters therefore match the same model names, while the original UTF-16 text is retained in the composer and request serialization. Malformed surrogate input produces no model suggestion. Tests cover canonical equivalents, preserved word boundaries and negation; the WPF verifier checks a decomposed message through V2 serialization without rewriting its code units.

The explicit `Son mesajın model önerisini yeniden değerlendir` button reconsiders the last successfully appended user message without calling Send or appending text. It remains available when image loading initially prevented selection. The message must still occur exactly once at the end of the current prompt; a changed, removed, repeated message or unsent new message is refused. Opening another request clears the retry token. Current notes and current image bytes are freshly captured and validated; an old image revision is not used as approval. The same conversion and model confirmations apply, including stale-state checks. No action is automatically resumed after image loading.

Image validation in this flow still runs synchronously on the UI thread through the existing bounded V2 serializer/Windows decoder; a large allowed image may temporarily pause interaction. This change does not claim responsiveness or cancellation of that decoder. Moving it off-thread needs a separate async lifecycle with immutable image snapshots, in-flight cancellation, dispatcher checks and confirmation revalidation; it was not mixed into this retry correction. No interactive performance or device tests were run here.

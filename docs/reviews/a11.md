# Agent 11: Core geometry review

Read-only production-code review. No WearCAD access or modifications.

## Findings

1. Finite-only coordinate validation is insufficient. Confirmed by compiled console probe: Distance((-1e308,0),(1e308,0)) returns NaN because coordinate subtraction overflows; SignedArea of a 1e200 square returns Infinity. Bounds2.Center also adds endpoints before dividing and can overflow. Persistence currently accepts these coordinates. Add a documented physical coordinate magnitude limit at geometry and import/persistence boundaries, validate calculated results, and compute center using Min + (Max-Min)/2 within supported bounds. Cover rejection in tests. This matters for corrupted/imported files reaching UI fit/area rather than ordinary garment sizes.
2. HasSelfIntersections is O(n^2), while persistence permits up to one million vertices per contour. Do not invoke this on UI thread for unrestricted imported contours. Apply practical point limits/cancellation or spatial indexing before production validation. This is a scalability risk, not a demonstrated current UI hang.
3. HasSelfIntersections is only an intersection predicate, not a valid-contour validator. Empty input returns false and PointInPolygon treats boundary points of a collinear polygon as inside. Before production output add explicit closed-contour minimum vertex count, area, duplicate vertices, and self-intersection validation. Preserve open polylines as valid drawing entities separately.

Ordinary mm-scale geometry cases are well covered by existing tests. Source includes stable translated area, transform output validation, correct adjacent-backtracking handling, and explicit duplicate closing point support.

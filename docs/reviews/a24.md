# Agent 24 — Grading robustness review

Independent source review found two concrete gaps and repaired them in GradingEngine.cs:

- A generated label could exceed the native format 1024-character limit, making an otherwise successful grade impossible to save. Null base names and unbounded size/rule names also passed. Generate now rejects invalid/oversized names before geometry work; rule names are bounded.
- GenerateSizes permitted 1000 sizes at 10000 vertices each, while intersection validation is quadratic and revalidates the base per size. This could stall the UI. Point count now follows the core 4096-vertex cap; batch output is capped at 200000 vertices and estimated quadratic work at 50 million operations before generation. Larger work must be split into batches. Empty batches now still reject null required arguments.

Seven regression tests added in GradingReviewTests.cs. Tests/build intentionally not run: root centralizes execution. No UI use, no WearCAD changes.

Existing implementation already rejects duplicate size labels ignoring case/outer whitespace, nonfinite steps, out-of-domain coordinates, collapsed or intersecting results, and orientation reversal. It leaves source geometry unchanged. Numeric output at the supported positive coordinate boundary receives a regression test.
